How far does an extraction error travel?

A four-stage pipeline over GST invoices, measured stage by stage as upstream errors are injected at a controlled rate.

Existing work evaluates each stage on clean input. In production every stage reads whatever the one before it produced. This measures the difference.

The finding. Errors do not spread evenly. Categorisation and reconciliation absorb upstream error. Anomaly detection amplifies it: its recall rises while precision collapses, because a misread digit looks exactly like a genuine inconsistency. At 30% upstream error the rule detector flags two thirds of all invoices, and the review queue stops being useful.

Reproducing this

Everything here is generated from a seed, so the dataset is never committed.

python -m gstpipe.generator.cli --businesses 30 --seed 2026
python -m gstpipe.render.cli --dataset data/synthetic/seed-2026
python -m gstpipe.inject.cli --dataset data/synthetic/seed-2026

The review application needs a Python runtime and Tesseract, so it is run separately — see DEPLOY.md.
